# Comparisons

Side-by-side results that draw on more than one study. One file per topic, for example `component-libraries.md`.

A comparison is only fair if every option was given the same task. Before comparing, write down:

1. **The task.** One concrete screen or feature that every option must build.
2. **The criteria.** Decide them before you start, so the result cannot be bent to fit a favourite.
3. **The versions and the date.** Libraries change; a comparison without a date misleads.

A starting set of criteria for UI libraries:

| Criterion | How to measure it |
|---|---|
| Accessibility | Keyboard-only use and a screen reader pass on the same screen |
| JavaScript shipped | Build output size for the same screen |
| Time to build the task | Hours, honestly counted |
| Custom code needed | Lines you wrote that the library did not cover |
| Theming | Effort to apply one custom brand (colours, radius, fonts) |
| Upgrade path | What an update requires: a version bump, or re-copying files |
| Documentation | Could you finish the task from the docs alone? |

Each comparison file links to the studies it is based on and ends with a recommendation and when it does not apply.
